## 一、答案与移动选型边界声明

在移动互联网高度普及的今天，智能手机已经成为绝大多数用户使用外网最频繁、最随身的终极终端。无论是在通勤地铁上刷 X（Twitter）与 Reddit、在咖啡馆连接公共 Wi-Fi 查阅资料、还是在跨国差旅中接收 Telegram 紧急工作通知，手机端连接的稳定性直接决定了用户的日常数字生活体验。

然而，相比于电源插座常驻、内存充裕且散热强劲的桌面电脑，**移动设备的网络环境具备三大极其苛刻的物理约束**：
1. **网络拓扑高频剧烈跳变**：手机在一天之内会频繁经历“从家庭千兆 Wi-Fi -> 离开小区切换至 5G 蜂窝基站 -> 进入地下车库短暂失联 -> 进入公司自动连接办公 Wi-Fi”的复杂链路转移。每一次物理链路切换，公网 IP 都会瞬间漂移，极易导致基于传统 TCP 的代理连接彻底挂起死锁；
2. **移动操作系统激进的杀后台机制**：无论是 iOS 的“墓碑机制”，还是国产安卓定制系统（MIUI/HyperOS、OriginOS、ColorOS、HarmonyOS）近乎偏执的省电策略，任何在后台持续消耗 CPU 或频繁唤醒网络套接字的第三方进程，都会在锁屏几分钟内被系统毫不留情地强行冻结或杀死，从而造成“锁屏后彻底收不到推送、点亮屏幕才能慢半拍刷新”的极差体验；
3. **有限电池容量与机身发热控制**：加解密大量网络数据包需要消耗手机处理器的密码学协处理器。如果客户端架构臃肿、或者选用了低效的加密协议，会导致手机在待机状态下异常发热并快速耗尽电量。

本专题存在的唯一目的，就是为广大移动端用户，建立一套**兼顾极致稳定性、极低耗电量与完全无感自动化的移动代理标准作业体系**。

## 五、移动端四大核心技术难点与深度调优手册

### 5.1 苹果 iOS 系统：NetworkExtension 框架与 On-Demand 深度配置

在 iOS 封闭的沙盒机制下，任何第三方应用程序在退到后台 30 秒后都会被操作系统彻底挂起（Suspended），失去执行 CPU 代码的能力。
**为什么代理软件能够在后台持续工作数天而不中断？**
秘密在于苹果官方提供的 **NetworkExtension（网络扩展）系统级 API**：
- 客户端在首次配置时弹出的“允许添加 VPN 配置”窗口，实际上是向 iOS 内核注册了一个由系统直接接管的虚拟网络接口驱动（Packet Tunnel Provider）；
- 当主应用程序被用户划掉或挂起时，这个底层的网络扩展线程依然由 iOS 系统内核作为独立守护进程高优先级托管；
- **On-Demand（按需连接）高级调优**：
  在 Shadowrocket 或 Loon 中，可以开启“On-Demand”按需连接规则：
  - 规则 A：当检测到连接的 Wi-Fi 名称为“Home-5G”（家里已部署软路由代理）时，自动将手机端代理**静默切断**，节约电量；
  - 规则 B：当离开家断开 Wi-Fi 接入蜂窝移动数据（Cellular）时，系统底层**毫秒级自动拉起代理**；
  - 这一机制完全由 iOS 内核原生调度，耗电量几乎为零，实现了真正意义上的“物理全自动无感巡航”。

### 5.2 安卓系统深度保活三部曲：彻底降服定制 ROM 的自杀机制

国产安卓手机的各大品牌厂商为了追求所谓“超长续航”，在系统底层内置了极其激进的内存杀手（Memory Killer）和电源守护进程。如果不做针对性放行，任何代理软件都难逃被强杀的命运。
必须严格执行以下三步深层放行：

1. **第一步：电池策略设为“无限制”（严禁智能省电）**：
   - 路径：`设置 -> 电池 -> 应用耗电管理 -> 选择客户端`；
   - 绝大多数系统默认为“智能推荐”或“受优化”，系统会在手机发热或锁屏时主动切断其网络套接字。必须手动改为**“允许后台活动”**或**“无限制（Don't optimize）”**；
2. **第二步：应用自启动与关联启动全开**：
   - 路径：`设置 -> 应用 -> 自启动管理`；
   - 开启客户端的“允许自启动”与“允许被其他应用唤醒”。这能确保即便在极端低内存状态下被系统偶尔回收，一旦有网络数据包发起，核心能在 0.1 秒内自动复活；
3. **第三步：多任务近期任务界面“加锁”**：
   - 从屏幕底部上滑呼出多任务卡片预览；
   - 找到客户端卡片，向下滑动或者长按，点击出现的**“小锁（Lock）”图标**；
   - 锁定后的应用卡片右上角会出现一个永久的小锁标，此时即便点击屏幕底部的“一键清理所有后台任务”，系统也不会误杀代理核心。

### 5.3 解决锁屏待机高耗电：为什么分应用代理（Per-App Proxy）是必选？

很多用户反映：“我手机只要开着代理，晚上睡觉待机一晚上就要掉 20% 到 30% 的电，怎么回事？”
经梯子参考实验室真机抓包定位，**罪魁祸首往往是国内的主流即时通讯与流媒体软件（微信、抖音、淘宝等）**：
- 国内 App 为了维持极高频的消息触达，每隔数秒就会向国内服务器发送高频的心跳长连接报文（Keep-Alive）；
- 如果开启了全局代理、或者规则分流判定较为繁琐，手机的代理核心必须无休止地对这些几百字节的心跳包进行解封装、规则树查找、再封包送出；
- 这导致手机的 CPU 永远处于微唤醒状态，无法进入深度的休眠低功耗（Deep Sleep）状态。

**彻底根治的终极对策：分应用代理（Per-App Proxy）**：
在 Android 客户端（如 Clash Meta for Android）的设置中：
1. 开启“分应用代理（Per-App Proxy）”开关；
2. 选择模式为**“仅代理选中的应用（Whitelist）”**或者**“绕过选中的应用（Blacklist）”**；
3. 将微信、企业微信、钉钉、QQ、支付宝、高德地图、各大网银以及国产游戏**全部勾选排除**；
4. 排除后，这些国内软件产生的所有海量心跳数据包，将直接由操作系统底层物理网卡直接收发，**完全不经过代理核心的加解密堆栈**。
实测经过此项调优后，安卓手机整夜待机 8 小时的代理耗电量可从 25% 骤降至 **2% 至 3%**，彻底消除续航焦虑。

### 5.4 蜂窝移动网络（4G/5G）基站切换卡死的协议根源与对抗

在高速行驶的高铁、地铁或者驾车过程中，手机会以每隔几十秒一次的极高频率在不同物理基站之间进行切换（Handover）：
- 在传统 TCP 握手体系下，每次切换基站会导致手机被运营商 NAT 网关重新分配一个新的局域网 IP；
- 远端的代理服务器如果依然在旧的四元组（原 IP + 原端口）上等待 ACK 应答，就会导致数据流陷入死锁超时，用户在手机端直观感受就是“信号明明是满格 5G，但网页就是无限转圈，非要开关一次飞行模式才恢复”；
- **破局之道：基于 UDP 的现代化协议（Hysteria 2 / TUIC v5）**：
  现代前沿协议基于 QUIC 体系开发，内建了革命性的 **连接迁移（Connection Migration）机制**。QUIC 连接不再以 IP 和端口作为唯一的会话标识，而是使用了一个独特的 **Connection ID（连接标号）**。即便您的手机公网 IP 变动了十几次，只要该 Connection ID 保持不变，远端服务器无需经历昂贵的三次握手与 TLS 重协商，就能毫秒级无感续传数据，从根本上终结了移动基站切换卡死的技术顽疾。

国内手机厂商基于 Android 开发的各大深度定制操作系统，在内存管理与进程调度算法上各有特点。为了让您在拿到新手机后能够一步到位完成配置，梯子参考实验室整理了华为、小米、OPPO、vivo 与三星五大品牌的专项保活指引：

## 七、移动蜂窝与多卡环境深度选型：eSIM、漫游卡与双卡分流

对于经常从事跨国商务、国际展会、出境旅游或跨境电商的移动用户，手机内部通常同时插有两张 SIM 卡（例如一张国内移动主卡用于收发电话短信，一张境外当地 eSIM 或香港漫游卡用于数据上网）。在这种复杂多卡环境下，如何规划网络分流至关重要。

### 7.1 境外漫游数据卡与境内代理的区别与协同
很多用户在出境前会开通中国移动或中国联通的“一带一路国际漫游流量包”。
**一个关键常识必须掌握**：
- 当您带着国内运营商的 SIM 卡漫游到海外（如日本或美国）时，虽然手机连接的是当地 SoftBank 或 AT&T 的基站，但根据国际电信联盟的漫游协议，**您手机的所有网络流量必须通过漫游通道（Home-Routing）无条件回传给中国国内的网关再出去！**
- 这意味着：即便您人已经坐在了东京的咖啡馆里，只要使用国内 SIM 卡漫游上网，**依然无法直接打开 Google 或 YouTube**！
- **正解方案**：在境外漫游状态下，手机依然需要配合代理客户端使用；或者在出境前通过支持 eSIM 的手机（如外版 iPhone 或海外版安卓）购买当地原生数据流量卡（如 Airalo、Ubigi、Nomad 等），享受完全合规且极速的当地机房出口。

### 7.2 双卡手机移动数据智能分流与防流量偷跑 SOP
在双卡双待手机上，操作系统的网络栈只有一条**主数据通道（Default Data Route）**：
1. **明确数据卡槽**：在手机“双卡与移动网络”设置中，将用于上网的大流量卡（如广电大流量卡或境外卡）明确指定为“移动数据默认卡”；
2. **关闭“智能切换上网卡”**：绝大多数国产手机内置了“主卡信号差时自动切换副卡上网”的所谓贴心功能。这往往是**导致副卡高额话费爆单的隐形元凶**！如果副卡是按每兆几毛钱甚至按漫游费计费的普通保号卡，主卡在电梯短暂丢信号时，副卡会自动偷跑几百兆流量，产生数百元扣费。请务必将该功能**永久关闭**；
3. **配合客户端分流规则**：在客户端内开启针对中国大陆 IP 的强制直连规则，确保在双卡移动状态下，微信打语音、刷朋友圈依然走国内骨干网，避免消耗昂贵的漫游或境外流量配额。

## 十一、移动端密码学与协议能耗深度评测：处理器硬件加速与续航博弈

在追求极致手机续航的过程中，许多用户往往只关注客户端的界面交互，而忽视了最底层的**对称加密算法与移动处理器（SoC）硬件特性的契合度**。加解密每一个进入手机的网络数据包都需要消耗芯片的运算周期，选对加密协议能够直接延长手机 1 到 2 小时的日常亮屏时间。

### 11.1 ARMv8 密码学指令集与 AES-256-GCM 硬件加速

现代智能手机的移动处理器（如苹果 A 系列与 M 系列芯片、高通骁龙 8 系列、联发科天玑 9000 系列）在微架构层面原生集成了 **ARMv8 Cryptography Extensions（ARM 密码学扩展指令集）**：
- 在配备了该指令集的现代中高端手机上，执行标准的 `AES-128-GCM` 或 `AES-256-GCM` 加密算法时，CPU 根本不需要动用通用计算核心（ALU），而是直接将数据包送入专用的硬件密码学加速管道（Hardware Pipeline）；
- 其加解密速率可达数十 Gbps，且 CPU 占用率几乎为零，发热量极低；
- **配置结论**：如果您使用的是近三年发布的主流中高端 iPhone 或 Android 旗舰机，节点协议优先挑选标准的 **AES-128-GCM 或 Trojan-TLS**，能够最大化榨取移动处理器的硬件加速红利。

### 11.2 中低端与老旧机型的能耗救星：ChaCha20-Poly1305 软件流密码

对于部分没有配备专用 AES 硬件指令集的老旧千元机、或者部分低功耗移动终端（如智能手表、电子书阅读器）：
- 如果强行运行复杂的 AES 块密码，手机处理器必须通过纯软件指令逐行执行矩阵轮密钥加变换（Round Keys），这会导致 CPU 的大核心持续处于高频高发热运转状态，机身发烫且耗电加剧；
- **救赎方案**：由著名密码学家 Daniel J. Bernstein 设计的 **ChaCha20-Poly1305** 算法；
- ChaCha20 是一种面向纯 32 位整数加法、异或和循环移位（ARX 操作）高度优化的流密码。即便在没有任何硬件加速器的简陋处理器上，纯软件执行的吞吐量也比软件 AES 快 3 倍以上，且内存占用极小；
- **配置结论**：如果您在备用机、老旧千元机或车载移动终端上使用代理，在节点选择上应优先挑选基于 `ChaCha20-IETF-Poly1305` 加密的节点，能够立竿见影地抑制机身发热并显著提升待机续航。

## 十二、移动端 DNS 泄露防范与运营商蜂窝劫持对抗实操

在移动网络环境下，运营商蜂窝基站（4G/5G）对于 DNS 的劫持与污染往往比家用固网光纤更加隐蔽且频繁。许多用户在手机上常常遇到“网页打开时被强行插入运营商流量提醒悬浮球”、或者访问特定学术网站时报出异常解析错误。

### 12.1 蜂窝基站默认 DNS 污染机制深度透视
当手机未接入 Wi-Fi 而是直接使用 5G 上网时，移动运营商的基站控制器会自动通过无线信令向手机下发本地的 DNS 服务器地址（例如各省的移动/联通专有 DNS）。
由于传统的 DNS 查询走的是明文的 UDP 53 端口：
1. 运营商的边缘接入网关可以随时对手机发起的域名查询进行**深度报文重定向（DPI 劫持）**，返回被污染的虚假 IP；
2. 手机在锁屏待机状态下，后台 App 发起的任何明文 DNS 解析，都会在运营商的日志系统里留下完整的历史足迹。

### 12.2 Android 专属“私人 DNS”与客户端 Fake-IP 双保险
在现代 Android 系统（Android 9.0+）中，谷歌引入了原生的**“私人 DNS（Private DNS / DNS-over-TLS）”**安全特性。
建议移动端用户配置以下双保险策略：
1. **系统层启用 DoT 纯净加密解析**：
   - 进入手机 `设置 -> 连接与共享 -> 私人 DNS`；
   - 选择“指定私人 DNS 主机名”，填入经过权威认证的纯净 DNS 提供商：例如阿里安全 DNS `dns.alidns.com` 或腾讯安全 DNS `dot.pub`；
   - 此时手机系统底层发出的所有未走代理的直连域名解析，全部经由 TLS 1.3 高强度加密传输，运营商基站完全无法中途篡改或明文嗅探；
2. **客户端层开启 Fake-IP 虚拟映射**：
   - 在手机 Clash 客户端中，确保开启 `enhanced-mode: fake-ip`；
   - 所有走代理的境外流量，在手机内部就已经被赋予了虚拟保留 IP，真实域名原样送入加密隧道前往远端香港/日本节点解析，在移动端实现了绝对的防污染闭环。

## 十三、移动端十分钟突击排障速查手册

在日常差旅移动出行中，一旦遇到网络故障，用户往往没有时间和条件像在电脑前那样打开命令行逐步调试。以下总结了移动端发生率最高的四大突发故障及十秒极速修复指南：

### 故障一：手机 Wi-Fi 图标旁边出现感叹号或叉号，显示“已连接但无法访问互联网”
- **真实根源**：手机操作系统的**网络连接连通性探测（Captive Portal Detection）**机制被代理规则误拦截。
  Android 系统在连接 Wi-Fi 时会默认向 `connectivitycheck.gstatic.com` 发送 HTTP 204 探测包；如果该请求卡在代理握手阶段，系统就会误判定当前 Wi-Fi 不可用并自动切断连接。
- **十秒自救**：
  在客户端分流规则中，确认将以下域名加入 `DIRECT` 直连白名单：
  ```yaml
  - DOMAIN-KEYWORD, connectivitycheck, DIRECT
  - DOMAIN-SUFFIX, msftconnecttest.com, DIRECT
  - DOMAIN-SUFFIX, captive.apple.com, DIRECT
  ```

### 故障二：升级了手机系统后，客户端打开即闪退报错
- **真实根源**：国产手机系统大版本升级后，自带的 **Android System WebView（系统网页渲染内核）** 版本不兼容，或者旧有的 VPN 虚拟网卡配置句柄发生死锁。
- **十秒自救**：
  1. 进入手机系统设置的“VPN”菜单，将原有的客户端连接配置彻底删除；
  2. 卸载客户端后，前往官网下载重新安装最新版本的 APK；
  3. 重新导入订阅并再次点击连接，允许系统重新生成全新的虚拟网络扩展句柄即可恢复。

### 故障三：在高铁上使用 5G 蜂窝网络时，手机发热严重且频繁掉线
- **真实根源**：高铁以每小时 300 公里高速穿行，手机每隔 15 秒就会切换一次基站，且在穿越隧道时信号频繁在 5G 与 4G 甚至 2G 之间来回震荡，导致手机射频功放（PA）全功率发射，引发剧烈发热。
- **十秒自救**：
  在手机系统设置中，将网络模式临时锁定为**“仅使用 4G / LTE”**。在高速移动场景下，覆盖更成熟、穿透力更强的 4G LTE 频段远远比频繁断连的 5G 更加稳定，且机身发热量能瞬间降低 40% 以上。

## 十四、平板设备（iPad 与 Android 平板）大屏协同专项配置

除了日常使用的智能手机之外，平板电脑（iPad 与各种安卓平板）已经广泛成为大学生、考研党、插画师与移动办公人员的大屏生产力核心载体。在平板设备上使用代理时，由于其独特的窗口多任务机制与大屏交互逻辑，存在着与手机截然不同的技术考量：

### 14.1 iPadOS 台前调度（Stage Manager）多窗口网络隔离
在配备 M 系列或 A12Z 以上处理器的现代 iPad 上，用户经常开启“台前调度（Stage Manager）”同时悬浮运行四个独立 App（例如一边打开 Safari 查阅海外顶会论文、一边使用 Goodnotes 手写做笔记、一边打开 YouTube 观看公开课、另一边悬浮着微信接收消息）：
- **多任务流量冲突防范**：
  在 iPadOS 高并发多窗口交互下，主应用程序切换极为频繁。建议在 iPad 上选用支持深度策略组分流的客户端（如 Shadowrocket 或 Loon），并将流媒体（YouTube / Netflix）与常规网页（Google / Wikipedia）分别绑定到不同的后端策略组；
  这样能够防止视频加载抢占全部带宽，从而避免在 Safari 中翻阅大型 PDF 文档时产生卡顿；
- **局域网文件互传（AirDrop / 隔空投送）防断连**：
  很多用户在使用 iPad 时反映：“为什么手机开着代理，给旁边的 Mac 电脑隔空投送（AirDrop）文件总是搜不到设备或发送失败？”
  这是因为部分旧规则集误将苹果本地局域网的多播 DNS 协议（mDNS / Bonjour，如 `224.0.0.251` 与 `_airdrop._tcp.local`）也送入了代理隧道。在客户端配置中，必须将 `*.local` 以及本地多播地址严格划归 `DIRECT` 直连白名单，确保大文件在局域网内以每秒上百兆的物理 Wi-Fi 极速直传。

### 14.2 安卓平板电脑模式（Samsung DeX / 华为电脑模式）与开发终端
在三星 Galaxy Tab、华为 MatePad 或小米平板上，用户常常连接实体外接键盘与蓝牙鼠标，切换进入“电脑模式（PC Mode / DeX）”进行轻度代码开发与文档排版：
- **Termux 本地 Linux 终端环境网络接管**：
  许多全栈开发者在安卓平板上安装了 **Termux**（安卓端强大的原生 Linux 终端环境），并在其中运行 Git、Node.js、Python 或 SSH：
  - 如果在平板的 Clash 客户端中仅开启了普通的代理模式，Termux 发出的很多底层套接字数据包可能会绕过代理导致 `git clone` 失败；
  - **正规打通 SOP**：
    在安卓平板上，务必开启 Clash 的 **“TUN 模式”**，并在分应用代理中明确勾选 `com.termux`；
    同时在 Termux 的 `~/.bashrc` 文件中，写入标准环境变量导出语句：
    ```bash
    export HTTP_PROXY="http://127.0.0.1:7890"
    export HTTPS_PROXY="http://127.0.0.1:7890"
    ```
    如此一来，无论是在平板上克隆 GitHub 仓库、安装 npm/pip 依赖包、还是通过 SSH 远程连接海外云服务器，都能享受到丝滑畅通的高速网络体验。

## 十五、手机端网络服务选型常见深度疑难解答 (FAQ)

### Q1：为什么小火箭在 App Store 中国区搜不到，必须要用外区账号？
**解答**：由于中国大陆地区相关互联网监管法规要求，所有涉及网络代理与特定网络隧道扩展功能的应用程序，在苹果中国区 App Store 均不予上架展示。
这不是软件本身出了故障，而是平台地域合规策略。
**正规获取 SOP**：注册一个属于您自己的独立美区、日区或港区 Apple ID，登录 App Store 即可正常检索并付费下载安装。购买一次终身随账号绑定，日后换新 iPhone 也可随时在已购项目中直接重新下载。

### Q2：手机和电脑能同时用同一个机场订阅链接吗？
**解答**：**完全可以，且这是全行业最普遍的标准用法**。
正规服务商提供的订阅链接是一个通用的网络配置接口。您可以在电脑的 Clash Verge Rev 中导入该链接，也可以在手机的小火箭中导入该完全相同的链接。
**唯一需要注意的限制**：核对您所购买套餐的“同时在线设备数上限（Device Limit）”。如果套餐规定允许 2 台设备同时在线，那么只要您家里电脑和外面手机加起来不超过 2 台，就能完全自由地同时畅享高速网络。

### Q3：开启手机代理后，微信收发消息会不会变慢，或者产生延迟？
**解答**：如果您使用的是默认的 **Rule（规则分流）模式**，微信完全不会变慢！
因为在规则模式下，微信的全部域名（如 `weixin.qq.com`、`tencent.com`）以及微信服务器所在的国内 IP 均被内置在 `DIRECT` 直连白名单中。微信的数据包完全不走海外节点，而是直接从您手机的真实宽带或 5G 走原生直连发出，速度和不挂代理完全一模一样。
只有当您误将客户端勾选为了 **Global（全局模式）** 时，微信才会因为绕道远端海外节点而变慢。

### Q4：安卓手机换机时，怎样快速将老手机上的配置迁移到新手机上？
**解答**：现代客户端提供了极简的备份与导出机制：
1. **订阅链接同步法（推荐）**：无需复制复杂文件。只需在新手机上安装好客户端，登录您所购买服务商的用户中心，点击“一键导入订阅”或复制订阅 URL 粘贴刷新即可，耗时不到 1 分钟；
2. **规则与配置本地导出法**：在 Clash Meta for Android 的“配置”面板中，点击配置卡片右上角的三点菜单，选择“导出为文件”。通过蓝牙、微信文件传输助手或电脑中转将该 YAML 文件发送给新手机，在新手机客户端中点击“从文件导入”即可完美复刻老手机上的所有自定义分流设置。

### Q5：为什么手机看 YouTube 可以跑满带宽，但打开某个小众网站却提示安全证书错误？
**解答**：这通常是由**网络节点的中间证书链缺失**或**本地系统时间偏差**引起的：
1. **检查手机本地时间是否精确到秒**：TLS 加密协议对客户端的时间戳有严苛的校验容差（通常不超过 5 分钟）。如果手机时间快了或慢了几分钟，会导致证书有效期校验失败；
2. **目标网站本身证书不健全**：部分海外小众个人博客使用了不被知名机构信任的自签名证书。如果确定该网站安全，可以在客户端高级设置中临时关闭“严格证书校验（Skip Cert Verify）”，但日常访问重要服务时请务必保持开启。

### Q6：手机开热点给笔记本电脑用时，为什么电脑打不开外网？
**解答**：手机开启移动热点（Personal Hotspot）时，手机内部的操作系统实际上创建了一个微型的局域网网桥：
- 默认情况下，手机的代理软件（如 VPN 接口）**仅仅接管手机本机用户态产生的流量**，而通过 Wi-Fi 热点穿透进来的笔记本流量，直接被操作系统底层的数据转发模块（NAT）绕过了代理直接推给了蜂窝基站；
- **解决对策**：
  1. 在手机客户端设置中，找到并勾选**“允许局域网连接（Allow LAN）”**；
  2. 记下手机当前的内网 IP（通常是 `192.168.43.1`）以及代理端口（如 `7890`）；
  3. 在电脑连接上该热点后，进入电脑的系统代理设置，手动将 HTTP 代理服务器地址填写为 `192.168.43.1`，端口填写 `7890`。此时电脑发出的网络请求就会强制送入手机的代理核心，实现畅通上网。

### Q7：双卡安卓手机切换“默认上网卡”时，为什么代理软件会自动断开并报错？
**解答**：当您在安卓系统设置中将默认上网 SIM 卡由卡 1 切换到卡 2 时，操作系统在底层实际上经历了以下剧烈重构：
- 操作系统强行注销了卡 1 绑定的网络接口（如 `rmnet_data0`），并重新向卡 2 的运营商基站申请激活数据承载信道（PDP Context），生成全新的网络接口（如 `rmnet_data1`）；
- 正在运行的 VPN 虚拟网卡接口会接收到底层物理网卡彻底注销的硬件事件广播；
- **解决方案**：在 Clash Meta for Android 的“网络设置”中，开启**“自动检测网络接口（Auto Detect Interface）”**，并将底层 TUN 栈由 System 切换为 **Mixed 或 gVisor**。在 Mixed 模式下，用户态协议栈具备极高的容错性，在底层 SIM 卡切换完成后 2 秒内便会自动重绑定新接口，避免崩溃。

### Q8：为什么手机锁屏后，Telegram 或 Gmail 的消息通知总是延迟几十分钟才弹出来？
**解答**：这涉及移动操作系统底层的消息推送通道分流问题：
- 在 iOS 上，所有合规 App 的离线消息通知全部经由苹果官方的 **APNs（Apple Push Notification service）** 服务器统一推送；如果您的代理规则将苹果官方的 APNs 域名（如 `push.apple.com`）误判定为了代理甚至拦截，就会导致推送断连；
- 在 Android 上，由于国内手机普遍剥离了谷歌的 GCM/FCM（Firebase Cloud Messaging）推送框架，Telegram 等软件在锁屏后必须依靠自己的后台常驻长连接来接收消息；如果系统在锁屏后杀掉了该长连接，消息就会严重滞后；
- **排查与修复**：
  1. 确认客户端分流规则中，苹果与谷歌的系统级推送域名被严格归入了 `DIRECT` 直连白名单；
  2. 在安卓手机中，将 Telegram 的电池优化设为无限制，并允许其自启动与常驻通知。

### Q9：为什么开启代理后，手机招商银行或工行 App 会闪退，或者提示“检测到代理环境”？
**解答**：国内主流手机银行、政务平台与证券炒股软件，为了防范网络电信诈骗与资金被中间人篡改，在客户端代码中内置了严格的**反代理与安全沙盒检测机制**。
当检测到操作系统的网络栈挂载了 VPN 虚拟网卡、或者存在系统全局代理时，安全模块会强制弹出警告并直接闪退退出。
**优雅解决办法**：
严禁使用全局代理！在 Android 端直接使用**“分应用代理”**将银行 App 完全排除在代理之外；在 iOS 端使用 Shadowrocket，其内置了针对国内各大银行的反检测白名单规则，确保银行金融数据 100% 走原生纯净基站通道，彻底消除误杀。

### Q10：怎样防止手机在后台开启代理时，云相册或 App 自动更新悄悄偷跑大量境外流量？
**解答**：这是许多初学者最容易蒙受经济损失的重灾区：
很多用户的手机相册开启了“连接 Wi-Fi 时自动同步全高清原片到云端”，或者开启了“应用商店自动下载最新游戏安装包”。如果此时在咖啡馆连接了 Wi-Fi 且开着代理，手机可能会在几个小时内静默上传和下载数十个 GB 的数据，导致宝贵的外网流量配额瞬间归零。
**防偷跑四项纪律**：
1. 在手机系统设置中，关闭“蜂窝网络下自动更新 App”；
2. 在 iCloud 或 Google Photos 设置中，将“移动数据同步”与“后台自动备份”开关关闭；
3. 在代理客户端中，确保配置了完善的 `Apple` 与 `Microsoft` 直连规则集，确保系统更新流量强制走国内直连源；
4. 服务商后台开启“流量消耗达 80% 自动邮件预警”功能，做到心中有数、提前管控。

### Q11：手机开启代理时，能否同时正常连接智能手表（如 Apple Watch / 华为手表）与车载蓝牙？
**解答**：**完全可以无缝共存，但需注意底层的局域网协议放行规则**。
智能手表与手机之间的通信、以及车载中控与手机的蓝牙配对：
- 基础的音频通话与媒体控制走的是短距离**蓝牙低功耗协议（Bluetooth LE / RFCOMM）**，该协议完全脱离了操作系统的 TCP/IP 虚拟网卡栈，因此不受任何代理软件影响；
- 而像 Apple Watch 与 iPhone 之间的高速健康数据同步、离线表盘下载、以及华为手机的“多设备协同”，则依赖本地 Wi-Fi 局域网协议栈；
- **排查建议**：如果发现连接代理后手表无法正常同步天气或通知，检查客户端的“局域网直连规则”，确保未将 `10.0.0.0/8`、`192.168.0.0/16` 以及 `link-local`（链路本地地址 `169.254.0.0/16`）误送入代理，即可确保手表与车载设备 100% 毫秒级秒连。
