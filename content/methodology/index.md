## 一、物理测试台架与接入环境标准

为了消除不同地区运营商带来的网络波动偏差，梯子参考实验室在华东与华南节点建立了标准化的双向测试台架：

1. **三网实体物理接入**：
   - 中国电信（China Telecom）千兆企业宽带（公网 IPv4 + 双栈 IPv6）；
   - 中国联通（China Unicom）千兆家庭宽带（骨干直连网络环境）；
   - 中国移动（China Mobile）千兆光纤网络（具有典型的复杂 CMI 路由与高动态 QoS 限制）。
2. **基准测试硬件**：
   - **桌面宿主机**：Intel Core i7-13700K / 64GB DDR5 / Intel I225-V 2.5GbE 原生物理网卡，运行 Windows 11 专业版（23H2+）；
   - **苹果生态宿主机**：Mac Studio M2 Max / 32GB 统一内存 / 运行 macOS 14 Sonoma 与 macOS 15 Sequoia；
   - **移动测试终端**：搭载高通骁龙 8 Gen 2 的 Android 14 终端（系统后台无电池白名单干预）与 iPhone 15 Pro（iOS 17/18 封闭沙盒环境）；
   - **软路由与网关**：Intel N100 四口 2.5G 软路由主机，运行官方原生 Linux Kernel 6.6 LTS，部署纯净版 OpenWrt 与 PassWall2 / HomeProxy。

## 二、五大核心物理参数的测量规范

市面上绝大多数商业测速往往利用多并发连接（Multi-thread）瞬间填满管道，这种跑分会掩盖严重的偶发丢包与长连接降级。梯子参考坚持采用更为严苛的工程级测算标准：

### 1. 单线程持续可用吞吐量（Single-Thread Throughput）
- **测算方法**：使用标准 `curl` 命令行与专用测试探针，通过代理隧道发起针对海外主流云服务商（AWS、Cloudflare R2、Google Cloud）单一大文件的 HTTP/2 GET 请求，持续下载 60 秒以上。
- **合格基线**：单线程平稳传输速率必须能够持续跑满 4K 60FPS 视频的高码率需求（即稳定在 35 Mbps 以上），记录下载过程中的瞬时下跌谷值。

### 2. 往返时延（RTT）与 P95 延迟抖动（Jitter）
- **测算方法**：在同一节点上持续发起 1,000 次以上连续 ICMP / TCP SYN 探测，分别记录中位数（Median RTT）、95 分位数延迟（P95 Latency）与标准差（Jitter）。
- **判定标准**：若 P95 延迟超过中位数 1.5 倍以上，或抖动超过 15 毫秒，则标记为存在严重路由抖动或骨干网拥塞风险。

### 3. 晚高峰丢包衰减率（Peak-Hour Loss Rate）
- **测算窗口**：严格选择每日晚间 20:30 至 23:00（国际出口高峰阻塞期）与凌晨 03:00（闲时基线）进行成对对比。
- **物理指标**：通过 TCP Reno/CUBIC 窗口变化曲线与 UDP 数据包到达率，计算丢包比率。丢包率持续大于 3% 的节点将被判定为不可用于低时延交互任务。

### 4. MTU 兼容性与 MSS 动态切片（MSS Clamping）
- **测试标准**：针对开启 TUN 虚拟网卡接管的客户端，验证其在标准 1500 字节以太网包穿越 VXLAN / 协议封装头（如 VLESS + Reality 或 WireGuard 封装）时，是否发生异常的网关级碎片丢弃。
- **推荐基线**：TUN 网卡 MTU 设置为 1400 或 1280 时的实际 TCP MSS 传输效率。

## 三、应用层任务稳定性专项复现流程

现代用户的大量任务集中于人工智能与终端构建，这要求网络不仅要跑得快，更要稳定不断线。

### 1. 人工智能大模型长对话保活测试（SSE Streaming Test）
- **测试流程**：模拟真实的 ChatGPT / Claude / Gemini API 与 Web 端请求，在同一条持久 HTTP 连接上持续接收 5,000 个 Token 的流式分块输出，全过程耗时 2 至 3 分钟。
- **通过门槛**：全过程不允许发生 `Connection Reset` 或断流重连，且出口 IP 必须通过主流 IP 风险评分库（IPQS、Scamalytics）的检测，欺诈分（Fraud Score）必须低于 30 分。

### 2. 终端开发者海量小文件高并发测试
- **测试流程**：在 Linux 与 macOS 终端执行包含数万个小文件的 Git 源码仓库克隆（例如 Linux 内核或 Chromium 子模块），以及 Docker Hub 官方镜像多层并发拉取。
- **核验指标**：排查在瞬间并发数百个连接时，客户端本地虚拟网卡是否出现文件描述符耗尽（Too many open files）或 TLS 握手假死。

## 四、数据发布与定期复核机制

1. **版本锁定标注**：所有测试长文与正文中，必须显式标注客户端的确切发行版本号（如 Clash Verge Rev v1.7.7、sing-box 1.10.7），杜绝因软件版本迭代导致的配置失效。
2. **拒绝利益捆绑**：实验室所有测试账号均为自费匿名采购或官方公开试用节点，绝不使用服务商专门配置的高权限“专属评测 VIP 线路”。
3. **公开勘误与复现**：任何同行或读者如果按照本方法论在相同网络环境下无法复现测试结论，均可通过技术交流邮箱申请实验室调取原始抓包日志（PCAP）并进行共同复核。
